# Копилка

Офлайн-журнал наличных для поездки. На главной нажми «Указать начальные наличные» и введи сумму, которая была до первого обмена. Если были только рубли, заполни RUB. Запиши уже сделанный обмен ₽ → $ с фактической датой и суммами. Обмен $ → ฿ добавь, когда он состоится. Чтобы исправить или удалить операцию, нажми на её карточку.

Ручной курс батов задаётся в настройках. Расход в иностранной валюте сохраняется вместе с курсом и рублёвым эквивалентом. Для трат в долларах можно отдельно указать курс USD. Обмены меняют только остатки.

На экране «Категории» можно добавлять и переименовывать категории. Удаление категории с историей переносит её в архив. Старые траты сохраняют связь с категорией, а восстановление возвращает её в список для новых трат.

## Экспорт и хранение

- **CSV** содержит по строке на операцию с постоянным ID, датой, типом, категорией, валютами, суммами и сохранённым рублёвым эквивалентом. Формат для русской локали Excel использует UTF-8 с BOM, разделитель «точка с запятой» и десятичную запятую. Для анализа расходов отфильтруй строки с `type = expense`.
- **JSON** содержит полный снимок, включая начальные наличные, текущие курсы и архив категорий. Суммы хранятся целыми числами в сотых долях валюты, курсы — в миллионных долях рубля за единицу.

Приложение хранит журнал в приватном файле SQLite `ledger.db`. При обновлении с версии на JSON открывается новый пустой журнал со стандартными категориями. Старый файл остаётся в папке приложения.

Траты, обмены, категории, начальные остатки и курсы хранятся в отдельных таблицах по схеме из `internal/store/migrations/001_init.sql`. У траты есть ссылка на категорию и сохранённый курс. Обмен содержит обе суммы в одной строке. Изменения журнала сохраняются одной транзакцией. Индексы по дате и категории пригодятся для отчётов.

Для изменения схемы добавь следующий файл в `internal/store/migrations`, например `002_add_operation_note.sql`. Приложение применяет недостающие файлы по порядку при открытии базы. Каждый файл выполняется в собственной транзакции вместе с обновлением `PRAGMA user_version`. Уже выпущенные файлы сохраняй без изменений. В новых файлах оставляй SQL изменений схемы или данных, а управление транзакциями и версией выполняет Go-код.

## Структура кода

- `internal/service` — модели журнала, правила учёта, проверка операций и расчёты.
- `internal/store` — SQLite, транзакции и миграции.
- `internal/ui` — экраны Fyne, навигация, тема и экспорт.

## Проверка

```powershell
$env:CGO_ENABLED = '1'
go test -tags ci ./...
```

Для локальных тестов нужен C-компилятор, совместимый с CGO. На Windows можно использовать GCC из MinGW-w64 или задать `CC` как `zig cc`, если Zig доступен в PATH.

Для запуска интерфейса на Windows из PowerShell с установленным MinGW-w64 в PATH:

```powershell
$env:CGO_ENABLED = '1'
$env:CC = 'gcc'
go run .
```

Если используешь LLVM-MinGW, укажи в `CC` путь к его `bin/clang.exe`. При отключённом CGO сборка интерфейса останавливается на пакете `go-gl`. CGO также нужен драйверу SQLite.

## Сборка Android APK

Установи Go и [настрой Android SDK и NDK для Fyne](https://docs.fyne.io/started/quick/). Задай `ANDROID_HOME` как путь к SDK, а `ANDROID_NDK_HOME` как путь к установленной версии NDK. Добавь каталог с Go-командами и Android Platform Tools в PATH.

```powershell
go install fyne.io/tools/cmd/fyne@v1.7.4
fyne package -os android/arm64 -app-id io.kopilka.travel -name Kopilka -app-version 0.0.13 -app-build 13
adb install -r Kopilka.apk
```

На телефоне для установки через ADB потребуется отладка по USB.

На Windows в Fyne CLI 1.7.4 нужно поправить упаковку адаптивных иконок. В копии исходников `fyne.io/tools` открой `cmd/fyne/internal/mobile/build_androidapp.go` и в вызове `apkwWriteFile("res/"+relPath, path, apkw)` замени `relPath` на `filepath.ToSlash(relPath)`. Собери CLI из этой копии командой `go build -o fyne.exe ./cmd/fyne` и используй полученный `fyne.exe` для сборки APK. Тогда пути в APK совпадут с путями из таблицы ресурсов Android.

## Публикация в GitHub Releases

После коммита с нужными изменениями создай и отправь тег версии. Например:

```powershell
git tag v0.0.14
git push origin v0.0.14
```

Workflow `.github/workflows/android-release.yml` запускает тесты, собирает APK для Android ARM64 и прикрепляет `Kopilka-android-arm64.apk` к релизу этого тега. Номер сборки вычисляется из версии тега, поэтому следующий тег должен быть больше предыдущего. APK подписан отладочной подписью Fyne для установки напрямую.
